JavaScript and Python. One runtime.

Poly embeds Bun and RustPython inside one Rust host, so TypeScript and Python can share a process, a runtime thread, and eventually a module system.

A polyglot runtime, not two commands

Keep the languages.
Lose the deployment split.

JavaScript orchestrates. Python computes. Rust owns the boundary. Poly is exploring what happens when those roles live in one executable.

01 / Bun

TypeScript without ceremony

Bun provides the JavaScriptCore runtime, TypeScript execution, bundling, npm compatibility, and the developer experience.

poly app.ts
02 / RustPython

Python embedded, not spawned

RustPython is linked into the executable with a frozen standard library. No Python installation or background process is required.

poly script.py
03 / Rust

A deliberate shared boundary

A Rust host function connects JavaScriptCore to a thread-local Python VM. The first bridge supports structured JSON values.

Bun.polyPythonCall()
04 / Distribution

Designed for one-file apps

The roadmap combines Bun bundles, frozen Python modules, and locked dependencies into a Windows or Linux executable.

poly build main.ts

Same process. Same thread.

The shortest possible bridge.

The current JS→Python path is synchronous and intentionally small. Values cross as a versioned JSON envelope while each VM retains ownership of its own objects.

  • No subprocess or stdio RPC
  • Persistent, thread-local RustPython VM
  • Captured Python stdout and traceback
  • Explicit path toward object proxies and imports

Project status

Working core.
Sharp edges.

Poly is an engineering prototype, not a CPython or Node.js replacement. Today it proves the embedding model and a minimal JS→Python bridge. Package compatibility, async interop, imports, and production release hardening remain active work.
